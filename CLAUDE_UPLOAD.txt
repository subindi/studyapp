# 스스로 개발 인계

## 목표

부모가 정한 일을 체크하는 데서 출발하되, 아이가 순서를 선택하고 계획·시작·완료·회고하는 습관을 만드는 서비스.
첫 사용자는 시윤(9세)과 승윤(7세). 나이와 자기주도 단계는 별개다.

## 읽을 순서

1. README.md
2. docs/01-product-policy.md
3. docs/02-screen-map.md
4. docs/03-design-system.md
5. source/의 세 HTML 원본과 designs/의 독립 실행 시안

## 작업 원칙

- 현재 폴더는 시안이며 production 앱이 아니다. 앱 개발은 app/에서 시작한다.
- 초안과 비교할 수 있도록 source/와 designs/는 보존한다.
- 시안의 전역 변수·샘플 데이터·체험 PIN·모의 저장을 운영 코드로 그대로 사용하지 않는다.
- 모바일·태블릿·PC에서 같은 데이터와 정책을 사용한다.
- 필수/선택, 하루 인스턴스/반복 원본, 완료/면제/이동을 분리한다.
- 중복 자유시간 지급, 재시도 중복 저장, 타이머 시간 초기화를 방지한다.
- 가족별 데이터 격리와 부모 권한은 서버에서 검증한다. PIN 화면만으로 보안을 보장하지 않는다.
- 주간 예시 숫자를 실제 활동 기록인 것처럼 표시하지 않는다.
- 구현 시작 전에 아래 정책의 미정 항목을 짧게 확인하고, UI 작업 등 독립 작업은 진행한다.
- 프레임워크·호스팅·DB·유료 서비스를 이미 확정된 요구사항이라고 가정하지 않는다.
- 실제 스마트폰 앱 잠금·AI 사진 판독·아지트·포인트 상점은 MVP에서 제외한다.

## 권장 개발 순서

공통 컴포넌트 → 아이 프로필/오늘 → 계획/타이머/완료 → 부모 할 일/확인 → 자유시간/회고 → 반복 생성/저장 → 알림/리포트 → 실기기 검증.

개발 확인 기준은 docs/01-product-policy.md의 검증 목록을 따른다.

# 서비스 정책 · 개발 인계용 정리

이는 대화의 정책 v1.0과 디자인을 개발에 넘기기 위한 정리다. 아래 '제안/미정'을 최종 승인으로 해석하지 않는다.

## 합의된 방향

- 가족 아래 여러 자녀 프로필. 아이별 할 일·자율권·기록·자유시간 분리.
- 승윤은 큰 퀘스트 카드, 시윤은 차분한 플래너. 권한은 연령이 아니라 자기주도 단계로 결정.
- 부모가 할 일과 반복 일정·필수/선택·자유시간을 설정한다.
- Lv.2: 아이가 순서 선택. Lv.3: 아이가 순서와 예상시간 선택.
- 한 번에 한 과제에 집중. 시작/일시정지/재개/완료 제공.
- 타이머는 시간 감각을 돕는다. 시간이 지났다고 강제 종료하거나 실패 처리하지 않는다.
- 아이 자기확인 → 필요 시 부모의 하루 단위 확인 → 자유시간 이용권 해제.
- 개별 과제당 게임 시간을 거래하듯 지급하지 않는다.
- 선택 할 일은 자유시간 해제 조건에 포함하지 않는다.
- 부모는 오늘만 면제/내일 이동/분량 변경/완료 인정 가능.
- 면제·이동은 완료 건수로 더하지 않는다.
- 도움 요청 전에 스스로 해볼 간단한 행동을 제안하되, 부모 도움 직접 요청도 가능.
- 짧은 회고와 성장 리포트. 형제 비교·순위·벌점·연속기록 초기화는 사용하지 않는다.
- 실제 앱 잠금, AI 사진 판독, 사진 인증, 캐릭터 아지트, 복잡한 포인트 상점은 MVP 제외.

## 구현 상태 모델 (제안)

할 일: 예정 → 진행 → 일시정지 → 아이 완료. 예외: 면제, 다른 날짜로 이동. 부모 확인은 하루 승인 상태로 별도 관리.
반복 원본과 날짜별 할 일 인스턴스는 별도 데이터다. 오늘만 조정해도 반복 원본은 변경되지 않는다.
기존 반복 원본 변경은 다음 생성일부터 적용한다. 새 할 일에는 '오늘에도 추가' 선택 제공.
자유시간: 잠김 → 확인 대기 → 사용 가능 → 사용 중/일시정지 → 소진.
일일 지급은 자녀+활동일 기준으로 한 번만 생성하고, 재시도는 기존 이용권을 반환한다.
타이머는 과제별 누적 기록을 유지한다. 재진입·화면 전환으로 시간을 초기화하지 않는다.

## 디자인에서 드러난 예외의 구현 기준 (제안)

- 오늘 필수 0개: 조건이 빈 목록이라는 이유로 자동 지급하지 않는다. 부모가 그날 자유시간을 승인한다.
- 모든 필수를 면제·이동한 날도 부모가 자유시간을 별도 확인한다.
- 완료 되돌리기: 아직 지급 전이면 조건을 재계산. 이미 지급·사용한 이용권을 자동 회수하지 않는다.
- 부모 승인만 있고 아직 이용권을 발급하지 않았다면 조건 변경 시 승인 유효성을 다시 확인한다.
- 이용권 사용 시작 이후 설정 변경은 현재 이용권 시간에 소급 적용하지 않는다.
- 오프라인 완료는 미동기화 표시와 재시도 경로 제공. 서버 확인 없이 부모 승인·보상 신규 발급하지 않는다.
- 저장 실패 시 작성 내용을 보존하고 재시도한다. 중복 클릭·재시도로 같은 일정을 중복 생성하지 않는다.
- PIN은 부모 화면 진입 보호 보조 수단. 인증 계정·가족 역할·서버 권한 검증을 함께 구현한다.
- PIN 복구는 부모 계정 본인 확인 후 가능. 시안 PIN 1234를 운영 기본값으로 사용하지 않는다.
- 도움/완료 알림 진입 시 가족 권한 확인 후 해당 자녀·할 일/하루 화면으로 이동한다.
- 무의미한 반복 알림을 보내지 않는다. 이미 처리된 요청은 처리 상태로 표시한다.

## 개발 전 짧게 확정할 사항

1. 웹/PWA로 먼저 만들지, 네이티브 앱부터 만들지.
2. 부모 로그인 수단과 가족 초대 범위.
3. 하루 마감 시각, 자정에 진행 중인 타이머와 남은 자유시간 처리.
4. 남은 자유시간 이월 여부, 자유시간 일시정지 허용 범위.
5. 하루 중 필수 추가/삭제가 기존 승인·이용권에 미치는 영향.
6. 오프라인 입력 보존 범위와 다기기 충돌 해결 규칙.
7. PIN 반복 오류 시 제한 횟수와 복구 인증 방식.
8. 알림 채널과 허용 시각.

가족 활동일 기준 시간대는 첫 사용자 기준 Asia/Seoul로 제안한다. 확정되지 않은 세부 정책은 임의로 숨겨 구현하지 않는다.

## 검증 목록

- 두 아이의 데이터가 섞이지 않는다.
- 순서 변경이 저장·재진입 후 유지된다.
- 예상시간 초과가 실패로 처리되지 않는다.
- 과제 타이머·자유시간 타이머가 새로고침/다기기에서 중복 증가하지 않는다.
- 선택 과제가 미완료여도 모든 유효 필수를 마치면 조건을 충족한다.
- 오늘만 분량 변경·면제·이동이 반복 원본에 반영되지 않는다.
- 부모 확인 없이 완료 클릭만으로 승인 필요 이용권이 열리지 않는다.
- 지급 요청을 연속 클릭하거나 재시도해도 일일 이용권은 하나다.
- 면제·이동은 완료 성과로 계산하지 않는다.
- 부모 모드 잠금·권한이 프런트엔드 버튼뿐 아니라 서버에서 검증된다.
- 저장 실패·오프라인에서 입력 내용이 유실되지 않고 상태가 분명히 보인다.
- 320px 모바일, 태블릿, PC에서 텍스트·버튼·입력이 겹치지 않는다.
- 실제 알림, 저장, 인증, 반복 생성 연결 후 통합 검증한다.

## 시작과 상태 · designs/02-start-and-states.html

- 처음 시작: 소개 → 가족/아이 등록 → 자율권 선택 → 첫 반복 할 일/평일 자유시간 → PIN 생성·재입력 → 완료 → 아이 첫 화면. 아이 추가 진입 포함.
- 모드 전환: 아이 선택 → 아이 화면 / 부모 PIN 입력·오류 → 부모 화면 / 계정 확인을 통한 PIN 복구 안내 / 아이 모드 전환 시 잠금.
- 예외: 할 일 없음 / 승인 대기 / 완료 되돌리기 / 자유시간 종료.
- 저장: 저장 전 / 저장 중 / 저장 실패·재시도 / 인터넷 끊김·재연결 / 저장 완료.
- 알림: 도움 요청 알림 → 해당 과제 / 전체 완료 알림 → 해당 자녀 완료 확인.
- 성장: 예시 기록이 있는 주간 리포트. 실제 기록과 예시를 구분할 것.
- 태블릿: 전체 순서와 현재 학습을 나란히 표시. 좁아지면 세로 배치.

현재 시안의 모든 상태가 하나의 완성된 앱에 연결된 것은 아니다. 개발 시 동일 데이터 모델로 통합해야 한다.

# 공통 디자인 규칙

## 방향

밝고 차분한 어린이용 생산성 앱. 캐릭터·게임 효과보다 할 일과 한 가지 행동을 중심에 둔다.
승윤은 큰 카드·아이콘·적은 글자, 시윤은 정돈된 목록·시간 계획. 데이터와 정책은 공통.

## 기본 토큰 · 라이트

| 용도 | 값 |
|---|---|
| 배경 | #F8F8F0 |
| 본문 | #263D32 |
| 보조 글자 | #637267 |
| 카드 | #FFFEFB |
| 구분선 | #DBE3D8 |
| 부드러운 강조 | #E8F0E1 |
| 주요 버튼 | #356346 |
| 주요 버튼 글자 | #FFFFFF |
| 보상/주의 배경 | #F5EDD7 |
| 주의 글자 | #735B2C |
| 오류 글자 | #9A3636 |

다크 대응값은 각 source HTML의 지역 CSS 변수/light-dark에 포함된다. 구현에서는 공통 theme tokens로 추출한다.

## 크기와 배치

- 모바일 기본 본문 16px, 보조 12–14px, 제목 25–27px.
- 터치 버튼 최소 높이 44–46px. 입력 필드 46–48px 이상, 글자 16px.
- 모바일 화면 안쪽 여백 18–24px. 카드 간격 12–16px.
- 아이 카드 반경 17–22px, 버튼 11–14px. 시윤 목록은 구분선 중심.
- 한 화면의 주요 행동은 한 가지. 도움·뒤로·취소는 낮은 강조.
- 태블릿: 전체 할 일과 현재 과제를 2열. 좁은 화면은 1열.
- PC: 사이드 메뉴와 본문. 850px 이하 상세 패널 세로, 640px 이하 상단 메뉴와 1열.
- 좁은 화면에서도 필수 내용과 행동을 가리지 않는다.

## 표시 규칙

- 색만으로 필수·완료·대기·오류를 구분하지 않는다. 글자와 체크 표시를 함께 쓴다.
- 학습 타이머: 남은 예상시간을 원형으로 표현, 실제 누적시간은 별도. 0이 되어도 계속 학습 가능.
- 자유시간: 남은 이용권 시간을 표현. 학습 타이머와 의미를 혼동하지 않는다.
- 상태 안내에 지금 상태·입력 보존 여부·다음 행동을 표시한다.
- 오류에는 벌점·실패자 표현을 쓰지 않는다.
- emoji는 시안용이다. 운영에서는 플랫폼 간 모양 차이를 확인하고 필요 시 일관된 라이선스 아이콘으로 교체한다.

실기기에서 대비·키보드 포커스·스크린리더·글자 확대를 검증한다. 아직 화면 이미지의 최종 출판물이나 인증된 접근성 디자인은 아니다.
